## Project


CloseUrCase — a legal-services platform frontend connecting citizens, lawyers, and admins. This repo is the **frontend only**: a client-rendered React SPA with no backend. All "persistence" is `localStorage`/`sessionStorage` backed by seed data — see Data layer below.

## Commands

Package manager is **Bun** (`bun.lock` is the lockfile of record; `package-lock.json` also exists but Bun is primary).

```
bun install         # install deps
bun run dev          # vite dev server on http://localhost:8080
bun run build        # production build
bun run build:dev    # development-mode build
bun run preview      # preview a production build
bun run lint          # eslint .
bun run format        # prettier --write .
```

There is no test suite/runner configured in this repo.

To check a single file for lint issues: `bun run lint -- path/to/file.tsx` (eslint flat config, same rules apply repo-wide — no per-package overrides).

## Architecture

### Routing — TanStack Router, file-based

Despite `@tanstack/react-start` being a dependency, **this app runs as a client-only SPA** — `src/main.tsx` calls `createRoot(...).render(<RouterProvider .../>)` directly (no SSR entry), and `vite.config.ts` uses plain `vite dev`/`vite build`, not the Start server build.

Routing itself is generated by `@tanstack/router-plugin` from `src/routes/*.tsx` into `src/routeTree.gen.ts` (auto-generated — never hand-edit it). Conventions (see `src/routes/README.md` for the canonical version):

- `index.tsx` → `/`; `about.tsx` → `/about`
- `admin.cases.tsx` → `/admin/cases` (dot-separated flat files, not nested folders, is the convention used throughout this repo)
- `$id.tsx` → dynamic segment (e.g. `citizen.chat.$id.tsx` → `/citizen/chat/:id`)
- `__root.tsx` is the single app shell (wraps every route with `QueryClientProvider` + `CitizenLanguageProvider`); preserve its `<Outlet />`
- Do **not** create `src/pages/`, `app/layout.tsx`, or other Next/Remix-style paths — this is TanStack Start/Router file-based routing only

### Three role-scoped areas

The app has three parallel dashboards under one route tree, each with its own layout wrapper and nav config:

- `/citizen/*` — `src/routes/citizen.tsx` wraps children in `DashboardLayout` using `src/features/citizen/nav.ts`
- `/lawyer/*` — same pattern via `src/features/lawyer/nav.ts`
- `/admin/*` — same pattern via `src/features/admin/nav.ts`

`src/layouts/DashboardLayout.tsx` is the shared shell (sidebar + header + notification bell + profile menu) parameterized by `role`/`roleLabel`/`nav`. `src/layouts/AuthLayout.tsx` and `PublicLayout.tsx` cover login/marketing pages.

Auth is real via Supabase edge functions: citizen login (`src/routes/citizen-login.tsx`) supports phone OTP and writes session data; lawyer login (`src/routes/lawyer-login.tsx`) authenticates advocates; admin login (`src/routes/admin-login.tsx`) authenticates superadmins.

### Data layer & Backend API

CloseUrCase is powered by a full Supabase Edge backend running Deno with Hono and `@hono/zod-openapi` under `supabase/functions/api/`:
- **REST Backend**: 108 registered endpoints covering Auth, Cases, Lawyers, Citizens, Daily Diary, eCourts, Payments, Agora Video Calls, Subscriptions, AI Legal Intelligence, and Admin.
- **API Documentation**: Canonical documentation is maintained in [`API_DOCUMENTATION.md`](file:///Users/sariyam/lomaa/closeurcase/API_DOCUMENTATION.md) and interactive Swagger UI at `/api-docs`.
- **Frontend Store**: `src/data/appStore.ts` acts as the reactive client cache and offline fallback. Service calls in `src/services/*` fetch authoritative data from the backend via `apiClient.ts` and sync into the store.
- **Subscriptions**: Components subscribe to store changes via `subscribeToStore(listener)`.

Domain types live in `src/types/index.ts` (`LegalCase`, `Lawyer`, `Citizen`, `DairyNote`, `CaseStatus`, `LegalCategory`, etc.) — start there when touching data shapes.

### UI components

- `src/components/ui/` — shadcn/ui primitives (New York style, Tailwind v4, `slate` base color, no RSC). Configured via `components.json`. Add new shadcn components with the standard `shadcn` CLI; don't hand-roll a primitive that already exists here.
- `src/components/app/` — app-specific composed components (e.g. `CaseChat`, `LexBot` the floating chatbot, `DataTable`, `ProfileForm`, `SettingsPanel`). These are the layer to extend for feature work; `ui/` should stay generic.
- Path alias `@/*` → `src/*` (see `tsconfig.json` and `components.json` aliases) — always import via `@/...`, not relative `../../` chains.
- Styling is Tailwind CSS v4 via the `@tailwindcss/vite` plugin (no `tailwind.config.js` — v4 is CSS-first, see `src/styles.css`).

### Citizen i18n

`src/features/citizen/i18n/` implements a small custom translation system (`CitizenLanguageContext` + `translations.ts`) supporting English/Hindi/Telugu (`CitizenLanguage = "en" | "hi" | "te"`), scoped to the citizen-facing flows only — it is not a general app-wide i18n framework.

## Conventions

- Formatting is enforced by Prettier (`.prettierrc`: 100-char width, double quotes, trailing commas) and wired into ESLint via `eslint-plugin-prettier`; `bun run lint` will fail on formatting drift.
- `@typescript-eslint/no-unused-vars` is deliberately turned off in `eslint.config.js` — don't treat unused-var warnings as a signal here.
- Importing `server-only` is blocked by an ESLint rule since this project doesn't use that Next.js convention; use a `*.server.ts` filename or `@tanstack/react-start/server-only` if server-only code is ever introduced.
